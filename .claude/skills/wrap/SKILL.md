# Wrap — 会话收尾

## 执行步骤

### Step 1：回顾本次对话做了什么

快速梳理本次对话的主要工作，分类判断：

- 建表/ETL 开发
- 取数/筛选
- 文档/配置整理
- 调试/数据质量排查
- 其他

### Step 2：逐类检查需要保存的内容

**只保存非显而易见的、下次对话不读代码就会忘记的信息。**

#### 基建相关 → `.claude/memory/feedback_dev.md`

值得保存：
- 踩到的字段陷阱（单位/枚举值与文档不符）
- 特殊的 JOIN 条件（不加某个过滤会出脏数据）
- Oracle/Doris 的非预期行为
- 建表方案中做了哪个非显然的设计决策，以及为什么

不保存：具体的 SQL 语句、参数值、某次运行的结果数字。

#### 项目进度 → `.claude/memory/project_status.md`

值得更新：
- 某张表已完成并上线
- 某张表进入新阶段（开发中 → 待补数 → 上调度）
- 新增了待实现的表

#### 取数相关 → `.claude/skills/query/memory/`

值得保存：
- 某表的特殊过滤条件
- 某字段的非预期行为
- 某个常用查询组合的注意事项

#### 业务规则 → `.claude/memory/business_rules_fund_data.md`

值得更新：
- 发现了新的字段含义或枚举值
- 某个已有规则需要修正

### Step 3：写入 memory

对每条值得保存的内容：

1. 判断归属（feedback_dev / project_status / query memory / business_rules）
2. 用一句话写清楚**规则本身**，加一行 **Why**（为什么重要/来自什么经历）
3. 写入对应文件，更新对应的 MEMORY.md 索引（如果有）

### Step 4：输出收尾摘要

简短告知用户：

```
本次会话已收尾：
- 保存了 N 条经验到 memory（列出文件名）
- [或] 本次对话没有新的跨会话价值内容，无需保存
```

---

## 判断标准

**值得保存的特征**：
- "下次遇到同样问题，不看这条记录就会再踩一次"
- "这个规则从代码里看不出来"
- "这个决策有背景原因，不记录下来将来会疑惑为什么这么做"

**不值得保存的特征**：
- 可以从 SPEC.md 或代码里直接读到
- 只是某次运行的具体数值
- 通用的 Python/SQL 知识
