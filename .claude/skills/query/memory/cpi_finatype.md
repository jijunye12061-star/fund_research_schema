# CPI_ISSUEBASICINFO.FINATYPE 取值

`SECURITYTYPECODE='058001001'`（A 股普通股本）下，FINATYPE 的实测分布：

| FINATYPE | 含义 | 板块覆盖 |
|----------|------|----------|
| `'001'` | 沪深主板 / 科创板 / 创业板 首次发行 | 60 / 000 / 001 / 002 / 003 / 300 / 301 / 688 / 689 |
| `'002'` | 北交所首次发行（**及少量主板异常情况**） | 主要是 920xxx，偶有 000xxx 个例 |
| `'002001'` | 增发（不是 IPO） | — |
| 其他 | 优先股、ETF 等非 A 股 | SECURITYTYPECODE 已过滤 |

**陷阱**：`FINATYPE='002'` 通常是北交所，但**不严格等于北交所**——历史上有少量主板代码（如 000032）也归在 002 里。建议联合判定：
- 用 FINATYPE 决定要不要拉
- 用 c_stk_code 前缀决定 board

# 北交所公募参与极少

北交所网下配售对象 ~98% 是私募 / 专户 / 银行理财 / 社保，**公募基金参与极少**。

实测 2025-06-01 ~ 2026-04-29 的 122 只北交所 IPO：
- 仅 1 只（920186）有公募参与（822 行配售）
- 其余 121 只全部由非公募投资者获配

下游"打新归因"业务因此对北交所贡献几乎为 0，符合业务现实。

# 上市当天 VWAP 缺失

注册制 IPO 的 c_sell_date = 上市日。如果跑 ETL 那天就是上市当天，`tb_stk_quote_daily` 当日数据可能还没入库（盘后才落表），导致 VWAP 缺失被 dropna 丢掉。

**应对**：
- 季度跑批一般在月末 +15 工作日，远晚于当月新 IPO 上市日，不会触发
- 手动 init 跑批如果赶上当天上市，受影响的几只下次跑批会补上（UNIQUE KEY 覆盖）
- 如要严格不丢，可在 _query_ipo_placement 里加 `i.NOTICEDATE <= sysdate - 5` 之类的延迟过滤
